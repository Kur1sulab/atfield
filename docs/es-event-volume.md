# EndpointSecurity `open` 事件量测量与降噪结论

> 数据来源：2026-11-19 本机实测（macOS arm64），汇总见
> `~/hermes-wiki/projects/HANDOFF-20261119-1835.md` 第六节 6.4。
> 本文档只做归档与解释，**未重新测量**；重测步骤见第五节。

## 一、为什么量这个

心之壁的凭据访问监控（`AEG-043` 等规则）订阅 ES 的 `open` 事件，靠文件路径
判断「有没有人读了不该读的凭据文件」。ES 是内核级事件源，粒度细到每一次
`open(2)`，代价是量极大：一个正常开发机上，编译器、语言运行时、包管理器
每天会打开几十万个文件。

量级不对会有两种失败：订阅太宽 → 事件风暴把判定线程压死、日志写爆磁盘、
真正的告警淹在噪声里；订阅太窄 → 边缘路径漏掉，等于没监控。所以第一件事
是把量测准，而不是先写规则。

## 二、实测数据

| 口径 | 事件率 | 相对裸订阅 | 说明 |
|---|---|---|---|
| 裸订阅 `open`（全部进程全部路径） | **1,679 条/秒** | 100% | 不可用 |
| 只订阅 `exec` | **8.4 条/秒** | 0.5% | 现网配置 |
| `open` + 只留真凭据路径 | **3.8 条/秒** | **0.23%** | 目标形态 |

噪声来源头部集中：`python3.14` 一个进程占 **69.8%**。这与「开发机天天跑
脚本」的直觉一致——解释器会反复打开 site-packages、`.pyc`、标准库。

## 三、三条结论

### 3.1 路径白名单是数量级降噪，不是微调

从 1,679 降到 3.8 是两个数量级以上，靠的不是调阈值，而是**在订阅层就把
路径收窄到真凭据集合**：`~/.ssh`、`~/.aws`、`~/.docker/config.json`、
`~/.npmrc`、`~/.pypirc`、`~/.kube/config`、`Keychains`、浏览器 Profile 下的
`Login Data` / `Cookies` 等。

这条与「AEG-043 走情报闸门定级」是互补的：订阅层管「要不要看」，闸门管
「看到了算不算事」。两层都要有，缺一层就退化成全量风暴或全量静默。

### 3.2 必须排除自身进程

心之壁自己会读这些路径做完整性校验（哈希、权限检查）。不排除就是自激：
自己的巡检被自己的规则判成「有人翻凭据」，每次刷新都产一条告警。

排除方式用 **进程身份**（pid + 可执行路径 + 代码签名），不要只按进程名——
名字可伪造，`python3` 可能是任何脚本。

### 3.3 冷启动需要基线学习期

新装机第一天，用户/IDE/包管理器会做大量首次访问（建索引、装依赖、`git clone`）。
这段流量不代表异常。建议：首次运行进入 24–72 小时学习期，只记录不出告警，
学习期结束把「高频 (进程, 路径) 组合」沉淀成白名单候选，由人确认后生效——
**不要自动生效**，否则攻击者只要在窗口期内跑一次就能把自己写进白名单。

## 四、给实现的三条硬要求

1. **路径白名单前置**：命中白名单的 `open` 不进判定队列（不是进队列后再过滤，
   那样 CPU 已经烧了）。
2. **排除自身进程**：按 pid + 可执行路径 + 签名三重判定；巡检进程在启动时
   把自己的身份注册进排除表。
3. **基线学习期**：学习期内只落库不告警；结束时输出候选白名单供人工确认。

## 五、怎么重测（可复现）

前提：root + 已授予 EndpointSecurity 的 TCC 授权（未授权时该采集器应显示
不可用，其余能力不受影响——这是设计上的降级，不是缺陷）。

```bash
# 1. 裸订阅量：只统计 open 事件，跑 60 秒
sudo eslogger open 2>/dev/null | pv -l -i 5 > /tmp/es-open-raw.txt
# 行数 / 60 ≈ 事件率（pv 的实时速率也行）

# 2. 现网 exec 口径
sudo eslogger exec 2>/dev/null | pv -l -i 5 > /tmp/es-exec.txt

# 3. 按进程聚合噪声 Top（找出该排除谁）
awk -F'"' '/"process"/{print $4}' /tmp/es-open-raw.txt | sort | uniq -c | sort -rn | head -20
```

测完对照第二节三行数据，偏差超过一个数量级就要重看白名单是否漏了整类路径。

## 六、已知边界

- macOS 26+ 的 `netstat` 不再输出常规 TCP/UDP 表，非 root 的连接归属依赖
  `lsof`，只看得到当前用户进程（见 README 第十二节）。
- ES 需要 root + TCC；未授权时采集器显示不可用，不影响其余能力。
- 本文数据来自**一台开发机**（M 系列、日常跑 Python/Node/Go）。服务器或
  纯办公机的分布会完全不同，换机型必须重测，不能把 3.8 条/秒当通用常量。
